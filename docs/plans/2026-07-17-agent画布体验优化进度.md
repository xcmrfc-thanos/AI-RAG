> 更新日期：2026-07-17
>
> 当前状态：Agent 画布功能整改完成；真实 18080 全链路门禁通过，仅保留前端全仓 lint 存量问题收口

> 推进方式：每个任务均执行“实现 → 自检 → 提交 → 更新进度 → 下一项”

## 一、目标

将当前仅能完成基础编排的 React Flow 画布，优化为接近 Dify / 扣子使用体验的 Agent 工作流工作台：节点易理解、拖拽与连线顺畅、配置即时生效、草稿可调试、运行问题可定位。

本轮保持以下边界：

- 保持 `schemaVersion=1` 和后端线性工作流执行模型。
- 暂不实现条件分支、循环、并行 DAG、多 Agent 协作和人工审批。
- 工具继续透传终端用户身份并遵守 Search / Document ACL。
- 新增节点优先复用系统已有只读接口，不开放任意 HTTP、任意 SQL 和高风险写操作。

## 二、当前问题基线

- [x] 节点只能点击添加，不能从节点库拖入画布。
- [x] 新节点按固定偏移堆叠，缺少自动布局、吸附和对齐反馈。
- [x] 页面连线说明与实际 Handle 方向相反。
- [x] 属性修改后必须点击“应用到节点”，容易遗漏。
- [x] 节点卡片不展示主要参数、输入输出和配置完整性。
- [x] 缺少明确的开始节点和结束节点，工作流语义不完整。
- [x] 试跑依赖已发布版本，不能直接调试当前草稿。
- [x] 缺少节点级运行状态、输入输出快照和错误定位。
- [x] 原始 JSON 与常用配置混在主流程中，学习成本偏高。
- [x] 前端允许自由连图，但后端只接受唯一线性链，缺少即时约束提示。

## 四、验收标准

- 用户无需编辑 JSON 即可完成一个可运行的知识库问答工作流。
- 节点可拖拽添加，也可在线性链中间快捷插入。
- 无效连接在前端即时阻止，并给出可理解的原因。
- 修改常用参数无需额外点击“应用到节点”。
- 当前草稿无需发布即可试跑，且不会生成公开可运行版本。
- 运行时能在画布上定位当前节点、成功节点和失败节点。
- 每个节点能够查看输入、输出、耗时和错误信息。
- 至少提供 3 个开箱即用模板和 5 个以上真实可执行节点。
- 所有工具沿用终端用户 Token、ACL、超时、审计和错误码边界。
- Agent 相关测试、构建与 18080 全链路集成门禁通过；全仓 lint 的历史问题继续单独治理。
