# Phase 7 验收收口修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 Phase 7 当前的启动环境误判、ACL/权限初始化缺口、Golden 索引数据缺口和验收脚本假通过，使在线验收失败时可靠返回非零，最终获得可信的 Phase 7 全绿证据。

**Architecture:** 保持现有六服务、Gateway 信任边界和 Agent 线性工作流不变。先修复环境与测试数据准源，再修复硬门禁的退出码传播，最后在同一环境重建 ES、完成双用户 ACL、普通用户 Agent 和 Golden 指标验收，并同步阶段文档。

**Tech Stack:** PowerShell 5.1、Java 21、Maven、Spring Boot 3、MySQL 8、Elasticsearch、Docker、Vitest/Vite。

---

## 审计基线

2026-07-17 实测结果：

- Docker 8 个容器 healthy，六个 JVM 服务在显式 Java 21 后均可启动。
- Auth/HMAC、Agent 管理员 Run、后端定向测试、前端测试与 build 通过。
- `editor` 创建私有文档返回 403，Search ACL 未执行到隔离断言。
- MySQL 存在 Golden 固定文档 `1000000000000000001`～`1000000000000000009`，但 ES 仅有 9 条旧 E2E 文档和 3 个 chunk；Golden keyword 为 0/12。
- Agent 冒烟默认使用不存在的 `user/user123`，普通用户权限断言被 SKIP。
- `verify-auth-ai.ps1`、`verify-rag-golden.ps1`、`verify-phase7-gates.ps1` 将上述失败降级为成功退出，导致 `verify-all.ps1` 虚假输出 `ALL PASS`。

- P0：验收脚本假通过、Search ACL 未 PASS、普通用户 Agent 验收被跳过。
- P1：Golden 索引未按固定题集数据重建，指标无法形成有效 baseline。
- P1：启动脚本错误沿用 Java 8，默认启动失败。
- P2：`/api/ai/models` 在 Stub 环境返回空列表、前端全量 lint 存量错误；单独治理，不阻塞本轮 Phase 7 主链路收口。

## 完成定义

以下条件全部满足才可宣称 Phase 7 完成：

- 默认环境可自动选择并验证 Java 21。
- Search ACL 连续两次 PASS。
- editor 可创建私有文档，tester 无法搜索或读取该文档。
- 普通用户 Agent view/run 与管理员 edit/publish 权限矩阵均有真实 API 证据。

- `verify-phase7-gates.ps1` 与 `verify-all.ps1` 不再接受硬门禁 SKIP/FAIL。
- 后端测试、前端测试和 build 通过。
- 文档状态与代码、活库配置、脚本输出一致。
